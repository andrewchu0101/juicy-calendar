## 使用者、工作與情境

主要使用者：覺得「逐一輸入時間數字」很麻煩、希望把時間看得見的人，首發為台灣使用者，在自己的 Windows 電腦上用桌面版安排一天或一週的時間（對應 G-01）。目前卡在：一般行事曆要靠輸入數字或填表單，排出來的時間不好視覺化。（此痛點目前只有專案擁有者的陳述，見 Brief 假設 A-01。）

主流程：開啟 App → 在側邊選一顆色球 → 拖到日曆某一天的某個時間放開 → 出現 120 分鐘的色塊 → 拖曳邊緣調整長度 → 雙擊命名。想精確輸入數字的人，可以點色塊打開右側面板直接輸入，這是備用路徑。

主要失敗與取消：球拖到日曆外放開、或拖曳中按 Escape，不會建立任何區塊；輸入不合法的名稱或數字，原值保留。每次變更都會寫進使用者選的資料夾（JSON 檔），重新開啟同一個資料夾，會看到相同的區塊。

## 故事與驗收條件

### US-01 不用打數字就能排出時間區塊（G-01、G-07）

身為想把時間看得見的人，我想用拖曳色球來排時間，以便不必輸入任何時間數字。

- **AC-01.1（成功）**：Given Windows 桌面版已開啟一個工作區，本週日曆可見，側邊有 6 顆預設球 When 使用者把「Coding」球拖到週一欄的 10:30 放開，再把該區塊的下緣拖到 13:00，再雙擊區塊輸入「寫 PRD」並按 Enter Then 週一出現 10:30–13:00、名稱為「寫 PRD」的區塊，顏色與球相同，Coding 球仍留在側邊可再次使用，且全程沒有在任何欄位輸入時間數字。
- **AC-01.2（拒絕，不產生副作用）**：Given 使用者正在拖曳一顆球 When 在日曆以外的地方放開，或按下 Escape Then 不建立任何區塊，工作區內的事件檔數量不變；放在日曆外時有小碎片消散的回饋；該球仍可再次拖曳。
- **AC-01.3（拒絕，不產生副作用）**：Given 一個名稱為「寫 PRD」的區塊正在編輯名稱 When 清空名稱（或只剩空白）並按 Enter Then 區塊保持原名稱「寫 PRD」，磁碟上的資料不變。輸入被拒絕時以還原原值為準，不另外要求顯示訊息（Q-03 已決）。
- **AC-01.4（體驗）**：Given 使用者在日曆空白處按住左鍵 450 ms，radial 選單已出現 When 游標移到其中一顆球上 Then 該球出現「呼吸」或「沿圓周跑的波」效果，游標移開即停止；系統設定 `prefers-reduced-motion` 時不播放；球身維持純色。（效果的具體樣式見待決 Q-05。）

### US-02 我的排程不會不見或被改壞（G-02）

身為把時間排進 App 的人，我想關掉再開還能看到原本的排程，且壞檔或重複開啟不會毀掉資料，以便放心使用。

- **AC-02.1（查看結果，持久）**：Given 使用者建立了 3 個有名稱的區塊 When 關閉 App 後重新開啟同一個工作區資料夾 Then 看到相同的 3 個區塊，時間、名稱、顏色都和關閉前一致。
- **AC-02.2（拒絕，不產生副作用）**：Given 工作區內有一個事件檔的內容是無法解析的 JSON When 開啟該工作區 Then App 正常開啟，其他事件照常顯示，畫面通知指出有檔案損毀，且該損毀檔案在磁碟上的內容完全沒被修改。
- **AC-02.3（拒絕，不產生副作用）**：Given 工作區資料夾已在視窗 A 開啟 When 使用者另開視窗 B 嘗試開啟同一個資料夾 Then B 不會寫入該資料夾並顯示說明，A 的資料不受影響。（B 是被阻擋開啟還是改為唯讀，留給 SRS 與設計階段決定；Q-01 已決。）

### US-03 我能在自己的 Windows 電腦上安裝，並用我熟悉的語言與時間格式（G-04、G-05）

身為台灣的一般使用者，我想安裝後直接看到繁體中文介面和習慣的時間格式，以便不需要懂開發環境就能使用。

- **AC-03.1（成功）**：Given 一台乾淨的 Windows 電腦 When 依 README 執行安裝檔、啟動、建立工作區並完成 AC-01.1，再解除安裝 Then 能成功安裝與啟動；解除安裝後 App 被移除，但使用者的工作區資料夾與其中的檔案仍在。（解除安裝保留使用者資料，Q-02 已決。）
- **AC-03.2（成功）**：Given 系統語言為繁體中文（台灣） When 第一次啟動 Then 介面顯示繁體中文；系統語言為其他中文（例如 zh-HK、zh-CN）時也顯示繁體中文（Q-06 已決）；系統語言為非中文時顯示英文；在設定切換語言後立即生效，重新啟動後仍維持。
- **AC-03.3（成功）**：Given Windows 的時間格式（區域設定）為 24 小時制 When 開啟 App Then 區塊上、右側面板、時間軸標籤的所有時間都是 24 小時制（例如 13:00）；Windows 為 12 小時制則全部是 12 小時制，與介面語言無關。App 不另外提供 12／24 小時的切換設定。
  - 變更紀錄（2026-11-04）：原寫「設定可選跟隨系統／12 小時／24 小時」，專案擁有者改為只跟隨系統；原因是右側面板的時間欄位為瀏覽器內建控制項，格式跟隨系統（見 SRS 原 U-02）。
- **AC-03.4（成功，免安裝版）**：Given 一台 Windows 10（1803 以上、64 位元）電腦，已具備 WebView2 執行階段 When 把免安裝版 .zip 解壓到任意資料夾、執行並完成 AC-01.1 Then 工作區檔案出現在與執行檔同層的 `data` 資料夾內；把整個資料夾複製到另一台電腦執行，看到相同的區塊與語言設定。
  - 變更紀錄（2026-11-04）：免安裝版為專案擁有者新增的範圍。AC 因此為 11 條，超過原訂的 10 條起點；10 條是規模起點，不是上限，不為湊數刪除必要驗證。

## 產品規則與體驗

正常體驗以拖曳為主：新區塊永遠是 120 分鐘，事件可重疊且不會被重新排列，編輯一個區塊不影響它的模板或其他區塊。右側面板保留，讓想輸入數字的人可以直接改名稱、日期、開始、結束與持續分鐘數。

| 情境／規則 | 使用者看見的結果與資料變化 | 來源／AC |
|---|---|---|
| 新區塊長度 | 一律 120 分鐘，之後可調整 | `PRODUCT.md`、NG-03、AC-01.1 |
| 區塊重疊 | 允許，只在畫面上共用寬度，時間不變 | `PRODUCT.md` |
| 備用輸入路徑 | 右側面板可直接輸入名稱、日期、開始、結束、持續分鐘；空白名稱與不合法的持續分鐘會被拒絕、原值保留 | Brief G-01、程式碼現況、AC-01.3 |
| 結束時間早於或等於開始時間 | 視為**不合法**：輸入被拒絕，還原為原值，資料不變；**不再**自動當成隔天。跨午夜的區塊仍可用拖曳，或改日期與持續分鐘建立 | Q-04 已決（現有程式行為會自動當成隔天，需改動）；AC 已滿 10 條，此規則由 SRS 的規則字典與邊界例子承接 |
| 資料夾格式版本比程式新 | 拒絕開啟，不修改任何檔案 | `ARCHITECTURE.md`、Brief G-02（現有行為，需在 Windows 驗證，由 SRS 與測試計畫承接） |
| 寫入失敗 | 變更留在佇列重試，不丟棄 | `ARCHITECTURE.md`、Brief G-02（同上） |
| 過去日期的欄位 | 區塊以降低的飽和度顯示 | `PRODUCT.md`（現有行為） |
| 只存在本機 | 無帳號、無同步、無遙測 | Brief NG-01 |
| 名稱與長度上限 | 事件名稱不得超過 30 個字；持續時間最長 7 天（10080 分鐘）；超過時輸入被拒絕、原值保留 | 專案擁有者 2026-11-04 決定；SRS 規則 R-3 |
| 介面排版 | 排版隨內容與視窗大小動態調整，不寫死尺寸 | 專案擁有者 2026-11-04 要求；SRS NFR-07 |

**G-03（Windows 穩定可用）不寫成使用者故事**：它是品質目標，由 SRS 的非功能需求與測試計畫承接。**G-06（深色模式）**已規劃，不屬於首次交付，不在本 PRD 的 AC 內。
