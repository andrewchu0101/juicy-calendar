## 2026-11-07｜票 029 回歸修正

- 關閉是包含 flush、訂閱、native root、writer lock 的同一個生命週期：記憶檔刪除失敗前不能放鎖；等待關閉時暫停持久化變更，失敗後恢復同步並通知。
- 磁碟 ID 即使符合格式也能是 `constructor`、`toString`、`__proto__`。比較實體是否存在要用 own-property；一般物件的 `in` 會把繼承屬性誤當實體。
- 新增模式與合法 ID 不共用字串 sentinel；模板編輯狀態改成有模式的 union。
- 時間格式測試要驗證實際日曆刻度，不能只驗工具列選項。12 小時中文及午夜 `+1` 在 56 px 欄寬會換行，改成 80 px 並保留單行／容納邊界測試；面板 fit 的手算邊界相應變成 956／452 px。
- 無效 UTF-8 與真正 I/O 失敗需要不同 IPC 代碼。只略過前者的事件／模板檔，不用 lossy 解碼，也不把權限問題當壞檔吞掉。
- 全域手勢 listener 仍要用目前日曆 ref 限制起始目標，並以側欄、工具列與面板的反例保護觸發範圍。

## 偏差紀錄

### 2026-11-07｜原生對話框也要由目前語言的字典提供文字

工作區資料夾對話框原本由 Rust 寫死英文，前端切換繁中不會影響它；改為由前端字典產生 title，Rust 驗證格式後只負責顯示。既有多語系測試只涵蓋網頁與設定檔，未檢查原生對話框的 IPC 邊界，現以中英兩種語言及 create／open 回歸並確認移除 title 會再紅燈；實際原生標題仍待人工確認。

### 2026-11-07｜捲動內容矩形不能當成可放置範圍

完整日曆 columns 在捲動後延伸到 sticky 日期標題下方，單看矩形會把標題誤認成可放置區；改用實際命中元素是否屬於 columns，拒絕被標題或浮層遮蔽的位置。原本拒絕測試只拖到日曆左側，沒有捲動後覆蓋區案例；新增保留選取與檔案內容的瀏覽器回歸，並驗證舊矩形判斷會再次失敗。

### 2026-11-07｜載入也須驗證事件長度下限

磁碟 schema 原本只驗證結束晚於開始與 7 天上限，沒有套用 AGENTS 的 1 分鐘下限，因此 30 秒事件仍能載入。既有測試只覆蓋零長度與超過上限，新增「30 秒拒絕／恰好 1 分鐘接受且零寫入」整合回歸；使用者確認後同步 SRS 與測試計畫，並驗證移除下限會再次失敗。

### 2026-11-07｜外部 ID 不能用一般物件的 setter 收集

合法 `__proto__` ID 在 repository 的一般物件賦值時觸發原型 setter，事件與模板因此沒有自己的可列舉鍵；改用無原型容器後，合法檔案能照常載入且不改檔。原測試只有一般 ID，未涵蓋與 JavaScript 原型同名的合法輸入；新增公開 loadWorkspace 整合回歸，並確認改回舊容器會失敗。

### 2026-11-07｜失敗的 flush 不能當作可以關閉

flush 原本只表示嘗試完成，stop 卻清空待重試佇列，導致寫入失敗時關閉遺失變更；現在以明確的成功結果決定是否停止訂閱、清空狀態或允許視窗關閉。既有測試只有「失敗後再 flush 成功」，未測「失敗時關閉」，新增公開工作區 API 的整合回歸並以移除保護條件再紅燈驗證。

### 2026-11-04｜面板的「結束早於開始」現況自動當成隔天，規格要求拒絕

- 規格說：結束時間早於或等於開始時間為不合法，拒絕並還原（PRD Q-04、SRS R-3）；現況程式會自動改成隔天的同一時刻。
- 發現方式：讀 `mutations` 的結束時間處理（2026-11-04，讀程式，未執行驗證）。
- 對齊方式與證據：票 004，TC-04 逐列驗證；現有測試若期待自動隔天，要列出名稱與依據後再修訂。
- 後續文件：SRS R-3 邊界例。

### 2026-11-04｜日期欄現況會把不存在的日期進位

- 規格說：日期必須是存在的日期（SRS R-3）；現況程式用 JavaScript 的日期建構，`2026-02-30` 會被進位成 3 月 2 日。
- 發現方式：讀程式推論（**未執行驗證**）。
- 對齊方式與證據：票 004，TC-04 的 `2026-02-30` 一列。
- 後續文件：專案擁有者已於 2026-11-04 同意修改現有行為。

## 規格誤解

### PRD Q-01、Q-03 的「ok」

- 提問是二選一或附條件的問題，回覆只有「ok」。我當時記為「此為我對 ok 的理解」，後來在 PRD 確認時一併被確認。
- 教訓：回覆沒有指名選項時，文件裡要寫出我的理解，讓審查者有機會糾正；不要把推測寫成已決。

### 「時間格式跟隨系統就好」

- 可以讀成「只有輸入欄位跟隨系統」或「整個取消 12/24 小時設定」。我採用後者，並修改了已確認的 PRD AC-03.3 與 Brief G-05，同時留下變更紀錄，最後由專案擁有者確認。
- 教訓：會改動已確認文件的解讀，要明講並留變更紀錄。

### 「10 當壞黨」

- 把 U-10 的回覆讀成「當壞檔」，已記入 SRS。教訓：打錯字時寫出我的解讀。

## 踩過的坑

- **e2e 結果每次不同**（2026-11-03）：同一份程式碼三次結果為 20／9／6 項通過。原因是拖曳輔助函式在最後一次移動後立刻放開滑鼠，此時拖曳尚未啟動；獨立腳本證據：放開前等 0 ms 為 0/5 建立事件，等 50 ms 以上為 5/5。修法見票 001（2026-11-04 完成）：`dragBall` 放開前先等 `.ball-dragging-source`，目標在日曆內再等 `drop-ghost`（日曆外不會出現預覽，所以不能一律等它）。修復前連跑 3 次為 22／9／16 項通過、失敗清單各不相同；修復後 3 次皆 29／29 通過。
- **Playwright 預設把瀏覽器裝到 C 槽**（2026-11-03）：跑 `playwright install` 前要先設 `PLAYWRIGHT_BROWSERS_PATH`。已改為 `D:\DevTools\playwright-browsers`，並設為使用者環境變數；新開的終端機才吃得到。
- **缺少 WebView2 時 App 靜悄悄地 panic 結束**（2026-11-04）：用 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 指向空資料夾模擬，結束碼 101，只在標準錯誤留一行英文，正式版沒有主控台，使用者什麼都看不到。panic 發生在 Tauri 事件迴圈內，無法用 `Result` 攔截，所以要在啟動前偵測（票 014）。
- **Python 非原始字串會破壞 Windows 路徑**（2026-11-04）：寫入含 `D:\DevTools\rust` 的文字時，`\r`、`\n`、`\t` 被當成跳脫字元，弄壞了 `CLAUDE.md` 的三行。改寫檔案時用原始字串，並在寫入後 grep 驗證。
- **在 Claude Code 用 `!` 執行指令時，反斜線路徑會被吃掉**（2026-11-04）：`!` 交給 bash 執行，`D:\Project\...` 變成 `D:Project...`，指令失敗。Windows 路徑一律寫成正斜線（`D:/Project/...`）。這是路徑跳脫問題的第二次出現（第一次是上面的 Python 字串），建議升級成 `AGENTS.md` 規則，待專案擁有者決定。
- **GitHub 信箱隱私保護會擋下推送**（2026-11-04）：帳號開啟「阻擋會洩漏私人信箱的推送」時，用私人信箱（本機 git 設定的 `andrewchu0101@gmail.com`）做作者的 commit 會被拒絕（`GH007`）。處理：用 GitHub 的無信箱位址 `<帳號編號>+<帳號>@users.noreply.github.com`，只設在這個 repo 的本機設定；已推送的歷史要改信箱就得重寫歷史，所以**第一次 commit 之前**就要設好。帳號編號用 `gh api user --jq .id` 查。
- **推送前先確認遠端的可見度與授權**（2026-11-04）：目標 repo 預設是公開且沒有授權條款，推送等於公開內容。先用 `gh repo view --json visibility,licenseInfo` 查，必要時先改成私人。
- **Escape 取消拖曳後，放置預覽殘留（產品競態，已修）**（2026-11-04，票 004a）：TC-02 單獨連跑 20 次全過，但 `--repeat-each=40 --workers=8` 失敗 6～9 次，失敗時 `drop-ghost` 永遠留著（不是變慢）。探針（暫時在 `useTemplateDrag` 的 `finish`／`move` 記錄順序）：15 次失敗**全部**是 `escape → finish → move`，24 次通過的都沒有 `finish` 之後的 `move`。原因：取消後 dnd-kit 延遲送出的 `onDragMove` 讓 `move` 重新設回 `pointerRef` 並重畫預覽。修法：`activeRef` 旗標，`finish` 後的 `move` 直接忽略。修正後同條件 40/40、120/120 通過。教訓：間歇失敗在單獨執行時不會出現，要用 `--repeat-each` 加多 worker 製造負載才重現。
- **`dragBall` 在預覽還停在中途點時放開（測試輔助函式競態，已修）**（2026-11-05，票 022）：magnet、overlapping、weekly/daily 的間歇失敗同因。基線 `--repeat-each=40 --workers=8`：overlapping 失敗 2／0／3、magnet 3／4、weekly and daily 0／0（同走 `dragBall`，本輪未重現）。失敗時收到的都是路徑上的中途點（目標 10:00 收到 09:30／09:40／09:50）。探針（頁面端記錄 pointer 事件與預覽 `top`，60 次中 5 次失敗）：預覽第一次渲染在 739 ms，`top: 90px`（中途點），之後 y=200／210／220 三個 pointermove 在 4 ms 內到達，輔助函式因「預覽可見」在 755 ms 放開，預覽尚未更新到最終的 120px。產品無誤。修法：放開前輪詢預覽 `y` 與目標差 ≤ 8 px（磁吸範圍），最後一段改單步移動（原本 10 px 小步與磁吸範圍有歧義）。修正後各兩輪 40×8 皆 0 失敗，完整 e2e 連續 3 次皆 63 passed、清單相同。教訓：①「元素可見」不等於「元素在最終狀態」，等的條件要是放開時真正會讀的狀態；②我先假設用 `ball-overlay` 的位置當訊號，量測發現它全程停在原位，假設錯誤，改用預覽；③紅燈測試用注入腳本延後 React 提交（`MessagePort.postMessage`）重現負載，僅延後處理函式（`elementFromPoint` 忙等）或單純延後提交都不會紅。紅燈約 20～30% 才紅，綠燈後 30／30，突變（容差 1000）7／30 轉紅。
- **拖曳到 7 天上限的 e2e 不必真的拖滿**（2026-11-04，票 005）：縮放允許超出格線（`allowOverflow`），把指標移到 ±14000 px 即可，不需邊緣自動捲動。
- **dnd-kit 之外，輸入框的 `maxLength` 不能拿來限制 30 字**（2026-11-04，票 003）：`maxLength` 以 UTF-16 單位計數，`👨‍👩‍👧` 一個字元佔 8 個單位，會誤擋合法輸入。名稱規則只靠 `validateTitle`（`Intl.Segmenter`）。
- **`beforeEach(() => mock.mockReset())` 會製造假的失敗**（2026-11-04，票 010）：箭頭函式回傳了 mock 本身，vitest 把回傳的函式當成清理函式，測試結束後又呼叫一次，`mockRejectedValue` 的 rejection 沒人處理，於是看似實作錯誤的 3 項失敗其實是測試寫法問題。`beforeEach` 一律用區塊 `{ ... }`，不要直接回傳 mock。紅燈要確認「是斷言失敗」，不是「未處理的 rejection」。
- **先前說「骨架階段就會過的測試」要補突變檢查**（2026-11-04，票 010）：`initLanguage` 吞掉讀設定錯誤這個行為，我先實作、事後才發現沒有測試；突變（不吞錯）全部測試仍過。補測試後才變紅。實作時每加一個 `try/catch` 或降級分支，就要有一個測試會因它而變紅。
- **Python 腳本寫入 TypeScript 時，反斜線會被吃掉或多出來**（2026-11-04，票 010）：假路徑 `C:\secret\path` 寫進檔案後變成 `C:\secret\path`，被 eslint `no-useless-escape` 擋下。測試用的假路徑改用正斜線（這是路徑跳脫問題的第三次出現，建議升級成 `AGENTS.md` 規則，待專案擁有者決定）。
- **複製 demo 後，Tauri `identifier` 與開發埠必須改掉**（2026-11-04，票 010 之後）：兩者相同會共用 `%APPDATA%\<識別碼>` 的 `last-workspace.txt`、`app-settings.json`，也共用 `localhost:1420` 的 `localStorage`，且 `strictPort` 讓兩邊不能同時 `npm run dev`。分叉專案的第一步就該改這兩個值。

- **Rust 不在 PATH**：每個要用 Rust 的程序都要先設 `RUSTUP_HOME`、`CARGO_HOME` 並加 PATH。
