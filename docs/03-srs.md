## 功能需求

## 規則與資料字典

主流程是：球放下 → 引擎依放開點算出時間（R-1）→ 建立事件（R-2）→ 使用者以拖曳或面板修改（R-3）→ 寫入資料夾（R-4）→ 下次開啟時逐檔驗證載入（R-5）。**狀態由誰決定**：事件 `id` 與 `startAt`／`endAt` 的初值由 App 的引擎決定，使用者只透過拖曳或面板間接修改；`schemaVersion` 由 App 決定；名稱、顏色、語言、時間格式由使用者決定。

**R-1 放開點 → 開始時間**（FR-01；現況）
- 放開點必須落在日曆欄內，否則不建立（以放開點下方的元素是否在欄內判定）。
- 時間以最近的整分鐘解析；磁吸預設開啟，放開點距 30 分鐘線 8 個螢幕像素內時吸附到該線；磁吸關閉則不吸附。
- 每一欄顯示一個「牆鐘視窗」：預設從當天 08:00 起，到隔天 03:00 止（共 19 小時）；位置依牆鐘分鐘計算。
- 例（預設縮放 1 像素／分鐘，視窗頂端為 08:00）：放開點在欄頂端下方 150 像素 → 10:30。放開點在欄頂端下方 1139 像素 → 02:59（隔天），此事件從 02:59 起，會被切成兩段，分別顯示在相鄰兩欄。
- 反例：放開點在側邊欄、工具列或右側面板上方 → 不建立。

**R-2 新事件欄位**（FR-01；現況）
- `id`：App 產生，格式 `evt_` 加隨機字串；符合 `^[A-Za-z0-9_-]{1,120}$`；使用者不可控。
- `title`：預設等於模板名稱（模板名稱同樣不得超過 30 字，U-11 已決）。
- `color`：複製模板當下的 `#RRGGBB`；之後改模板不影響已建立的事件。
- `startAt`：R-1 的時間；`endAt` = `startAt` + 120 分鐘，以**經過的時間**計算，不是牆鐘分鐘。
- 例（America/New_York）：2026-11-01 00:30 EDT 放下，結束時間為 01:30 EST（夏令時間結束日；經過 120 分鐘，牆鐘只差 1 小時）。台灣沒有夏令時間，不受影響。

**R-3 修改事件**（FR-02、FR-03）
- 拖曳上緣：結束不變，開始被夾在「結束減 1 分鐘」之前（拖過頭時邊緣停在邊界、不再移動，長度維持 1 分鐘；現況，U-04 已確認）。拖曳下緣：開始不變，結束至少為開始加 1 分鐘。兩種拖曳的總長度上限都是 10080 分鐘（7 天），到達上限時邊緣停在上限。
- 名稱：去掉前後空白後必須非空，且不得超過 30 個字（U-03 已決）；字數以使用者看到的字元計，中文字、英文字母、數字、符號各算 1 個；超過 → 拒絕（比照其他不合法輸入，還原原值）。模板名稱適用相同規則（U-11 已決）。
- 日期欄：格式 `YYYY-MM-DD`，必須是存在的日期；事件整段平移到該日，保留開始的時刻與長度。格式錯誤 → 拒絕。
- 開始欄：`HH:mm`（時 0–23、分 0–59），套用在**開始當天**；長度不變，結束隨之平移。格式錯誤 → 拒絕。
- 結束欄：`HH:mm`，套用在**結束目前所在的日期**（新增，U-06 已確認）；結果必須**嚴格晚於**開始，且總長度不得超過 10080 分鐘，否則拒絕。
- 持續分鐘欄：必須是有限數字且 1 ≤ 輸入值 ≤ 10080（7 天，U-03 已決）；範圍以**輸入值**判斷，通過後非整數才四捨五入；結束 = 開始 + 分鐘。空字串、非數字、小於 1、大於 10080 → 拒絕。
- 邊界例（事件為週一 10:30–12:30）：

| 輸入 | 預期 |
|---|---|
| 結束 `10:30` | 拒絕（等於開始） |
| 結束 `09:00` | 拒絕（早於開始；不再當成隔天） |
| 結束 `10:31` | 接受，長度 1 分鐘 |
| 結束 `24:00`、`9:5` | 拒絕（格式不合） |
| 持續分鐘 `0`、`0.4`、`abc`、空白 | 拒絕 |
| 持續分鐘 `1`、`1.4` | 接受，長度 1 分鐘 |
| 持續分鐘 `900` | 接受，結束為隔天 01:30（跨午夜的建立方式） |
| 持續分鐘 `10080` | 接受，長度 7 天 |
| 持續分鐘 `10081`、`10080.4`、`1e12` | 拒絕（超過 7 天） |
| 名稱 `   `（全空白） | 拒絕，保持原名稱 |
| 名稱 30 個中文字 | 接受 |
| 名稱 31 個中文字（或 31 個英文字母） | 拒絕，保持原名稱 |

- 跨午夜事件（週一 23:00–週二 01:00）：結束 `02:00` → 週二 02:00，接受；結束 `22:00` → 週二 22:00，接受（長度 23 小時）；結束 `23:00` → 週二 23:00，接受。因為套用在結束所在的週二，不會變成不合法。
- 拒絕的共同結果：欄位還原為原值，事件檔不被改寫，沒有新增或刪除檔案。

**R-4 寫入**（FR-05；現況）
- 一個實體一個檔：`events/<id>.json`、`templates/<id>.json`、`settings.json`、`workspace.json`。檔名必須等於 `id`。
- 變更與上次寫入的狀態比對後，依檔案排入佇列、合併、依序寫入；寫入失敗會留在佇列重試。
- 新工作區的 `workspace.json` 最後寫入，所以資料夾只有在內容完整時才算工作區。

**R-5 載入驗證**（FR-06；現況）
- 事件檔必須通過格式驗證：`id` 合規、`startAt`／`endAt` 為含時差的 ISO 時間、`color` 為 `#RRGGBB`、**`endAt` 嚴格晚於 `startAt`**。檔名不等於 `id` 也算壞檔。
- 壞的事件或模板檔：略過、通知、不改檔。
- 事件長度超過 10080 分鐘（7 天）的既有檔案，也視為壞檔：略過、通知、不改檔（U-10 已決）。名稱超過 30 字的事件或模板既有檔案也視為壞檔：略過、通知、不改檔（U-11 已決）。
- `settings.json` 損毀：另存為 `settings.corrupt.json`，改用預設值並通知（這是**會寫入新檔**的例外，與事件檔不同）。
- `workspace.json` 缺少或損毀、或 `schemaVersion` 比本程式新：拒絕開啟。
- `schemaVersion` 比本程式舊：先寫入相容的 `settings.json`，成功後才提升 `workspace.json` 的版本（開啟舊工作區會升級其格式）。

**R-6 資料隔離**（FR-01、FR-05、FR-07）
- 事件複製模板的顏色；編輯或刪除模板不改變既有事件，編輯事件不改變模板或其他事件。
- 前端不接觸絕對路徑；只能讀寫工作區根目錄內的允許檔案：`workspace.json`、`settings.json`、`settings.corrupt.json`、`templates/<安全名稱>.json`、`events/<安全名稱>.json`。
- 測試用資料與真實使用者資料隔離（測試使用暫存位置，不寫入真實工作區）。

**R-7 語言與時間格式**（FR-09、FR-10；新增）
- 語言取值：`繁體中文`、`English`。第一次啟動：系統語言以 `zh` 開頭 → 繁體中文，否則 → 英文；取不到任何語言資訊時 → 英文（2026-11-04 決定）。
- 時間格式：無設定項目，一律跟隨 Windows 的時間格式。例：系統為 24 小時制，下午一點顯示 `13:00`；系統為 12 小時制，英文顯示 `1:00 PM`，繁體中文顯示 `下午 1:00`；繁體中文的午夜暫定為 `上午 12:00`、正午為 `下午 12:00`，時間範圍的寫法與其餘細節等 UI 實作時再微調（2026-11-04 暫定決議，不阻塞驗收）。
- 語言設定屬於這台電腦，不屬於工作區：同一個工作區資料夾放到另一台電腦開啟，語言由那台電腦決定。免安裝版例外：語言設定存在與執行檔同層的 `data` 資料夾，隨資料夾移動。專案擁有者希望存放在使用者的「文件」資料夾；實際位置與注意事項見 U-01 的設計輸入。

**R-8 免安裝版資料夾**（FR-11；新增）
- 免安裝版的 `data` 資料夾就是一個一般的工作區，沿用既有格式：`workspace.json`、`settings.json`、`templates/<id>.json`、`events/<id>.json`；不使用單一 `events.json` 或資料庫（U-09 已決）。因此壞檔略過（R-5）、單一寫入者（FR-07）、原子寫入（NFR-02）對免安裝版同樣適用。
- 免安裝版如何決定使用 `data` 資料夾、首次執行是否自動建立工作區，由設計階段決定。

## 品質需求

- **NFR-01｜測試可重複（G-03）**：同一份程式碼在同一台機器上連續重複執行自動測試，通過與失敗的項目必須相同。驗證：連續執行 e2e N 次並比對結果。**N 沒有依據，記為待量測**。已知基準：2026-11-03 同一份程式碼三次結果不同（20／9／6 項通過），原因為拖曳測試在放開前未等待拖曳狀態完成，詳見 `docs/HANDOFF.md`。
- **NFR-02｜寫入不損毀資料（G-02）**：寫入使用「先寫暫存檔、同步、再改名」的原子方式；寫入中途失敗時，原檔仍是完整的舊內容。驗證：Rust 測試（現有 5 項）與註入寫入失敗的測試。
- **NFR-03｜離線與不對外連線（Brief 限制；2026-11-05 依專案擁有者指示拆成三個不同的要求，不得混為一談）**：
  - **NFR-03a｜所有功能可離線使用**：在沒有網路的電腦上，建立、編輯、儲存、重新開啟工作區都能運作，不依賴任何外部服務。驗證：在斷網環境實測。**目前未驗證**（e2e 與桌面煙霧測試沒有刻意斷網）。
  - **NFR-03b｜App 自有程式與依賴不主動對外連線、無遙測**：我們寫的前端與 Rust 程式，以及它們帶進來的依賴，不發出連線。驗證：安全政策（CSP）只允許本機 IPC、原始碼掃描（測試計畫 TC-15）。**目前僅部分達成**：前端 TypeScript 與 CSP 已由 TC-15 檢查通過；Rust 程式、Cargo 與 npm 依賴、Tauri 外掛權限**尚未查**（票 024）。
  - **NFR-03c｜包含 WebView2 的整個行程樹零對外連線**：App 執行期間，App 與它所有子行程（含 `msedgewebview2.exe`）沒有任何非本機的連線。驗證：M-06 正式監看。**目前未達成，且不得當成已達成**：2026-11-05 的預跑中，WebView2 的瀏覽器行程在 App 啟動後約 3 秒內對非本機位址的 443 連接埠建立連線（見測試計畫「M-06 預跑紀錄」）；那不是我們的程式碼，但屬於 App 的行程樹。NFR-03c 要保留、改寫或以哪些控制達成，**由專案擁有者決定**（U-13、票 024）；決定與調查完成前，不得對外宣稱「完全不連網」。
  - 例外：僅安裝程式為取得 WebView2 可連網（見 FR-08）。
- **NFR-04｜舊工作區可升級（G-02、G-05）**：加入多語系後，既有（格式版本 2）工作區仍可開啟，原有事件與模板不遺失。因為語言設定存在電腦層級而非工作區，工作區格式是否需要提升版本由設計階段判斷。驗證：以版本 2 的樣本資料夾開啟並比對事件。這會提升 `schemaVersion`（`AGENTS.md` 規則 8）。
- **NFR-05｜Windows 可安裝（G-04）**：在乾淨的 Windows 上完成安裝、啟動、解除安裝，支援範圍為 Windows 10 1803（組建 17134）64 位元以上。注意：最低版本 1803 是已停止更新的舊版本，取得該版本的測試環境可能有困難；若只在較新的 Windows 10／11 驗證，1803 標為**未驗證**，不宣稱通過。驗證：人工在乾淨環境執行（Manual Pending，無法以自動測試取代）。
- **NFR-06｜效能**：拖曳時預覽跟隨游標的延遲、啟動時間，目前**沒有基準或需求來源，全部記為待量測**，不訂數值。
- **NFR-07｜排版隨內容與視窗調整（專案擁有者要求）**：介面排版必須動態調整，不可寫死尺寸。在現有最小視窗尺寸（900×560，來自現有視窗設定）下，以及兩種介面語言、30 個全形字的名稱時，文字不溢出其容器、不遮蓋其他元件；區塊太短放不下名稱時的呈現方式由設計階段決定。驗證：以 30 個中文字名稱，在兩種語言與最小視窗尺寸下目視或截圖檢查。
- **不適用**：安全性中的身分驗證與權限（無帳號、無網路）；可用性百分比（單機 App）。
