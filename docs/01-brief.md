## 問題與證據

**誰、什麼情境**：像專案擁有者一樣的人，在安排一天或一週的時間時，覺得「逐一輸入開始與結束時間的數字」很麻煩，而且這樣排出來的時間不好視覺化。（來源：專案擁有者的訪談陳述。）

**目前如何處理、造成什麼影響**：一般行事曆與待辦工具要靠輸入數字或填表單來排時間，操作偏「管理」而不是「看著時間排」。影響：**待確認**。目前沒有對其他使用者的訪談、觀察或使用數據，只有擁有者本人的經驗。

**尚未核實的前提**（詳見下方假設）：除了擁有者以外，確實有一群人有同樣的痛點；用拖曳色球排時間，比輸入數字更快或更輕鬆。

**現況**：已有一個一次性產生的 demo（拖曳色球到日曆產生 2 小時區塊、可拖曳調整、雙擊命名、右側面板編輯、復原／重做、資料存成使用者資料夾內的 JSON）。2026-11-03 在 Windows 的基準線：`typecheck`、`lint`、單元測試 48 項、Rust 測試 5 項通過；e2e 因測試腳本的時序問題結果不穩定（已查出原因，尚未修）；桌面版尚未在 Windows 實際啟動過。

## 目標與成功判準

### G-01｜不用輸入任何時間數字，就能排出一個命名好的時間區塊

- 怎麼判斷：在 Windows 桌面版手動走一遍「選球 → 拖到日曆 → 拖曳邊緣調整長度 → 雙擊命名」，全程不需要輸入任何時間數字。右側面板的時間輸入欄位保留，作為想精確輸入數字的人的**備用路徑**，不是主要路徑。
- 目前基準與目標：未量測。可取得的代理證據：完成一個命名區塊所需的操作次數（尚未量測）。

### G-02｜使用者的排程資料不會遺失或被默默覆寫

- 怎麼判斷：壞檔會被略過並提示、版本太新的資料夾會拒絕開啟、寫入失敗會重試（demo 已有這些行為，需在 Windows 上驗證）；**同一個資料夾同時只有一個視窗能寫入**（新增，做法留到設計階段）。
- 目前基準與目標：基準未量測；目標是上述行為在 Windows 上都有測試或手動驗收證據。

### G-03｜Windows 桌面版穩定可用

- 怎麼判斷：桌面版能在 Windows 啟動並完成核心流程；自動測試結果穩定、可信（連續重複執行結果一致）。
- 目前基準與目標：桌面版 Windows 啟動 **未驗證**；e2e 同一份程式碼三次結果為 20／9／6 項通過，不穩定。目標：穩定通過。

### G-04｜一般人可以在自己的 Windows 電腦上安裝使用

- 怎麼判斷：產出 Windows 安裝檔；在一台乾淨的 Windows 上依 README 完成安裝、啟動、解除安裝。另提供免安裝版（.zip）：解壓到任意資料夾即可執行，資料放在與執行檔同層的 `data` 資料夾，整個資料夾可搬到另一台電腦使用（2026-11-04 新增）。程式碼公開在 GitHub。
- 目前基準與目標：目前打包設定只有 macOS 的 `app`，**沒有 Windows 安裝檔設定**。安裝檔**不簽章**（見 NG-05），SmartScreen 警告須寫入 README 的已知限制。

### G-05｜介面支援英文與繁體中文，時間格式跟隨系統

- 怎麼判斷：首次啟動跟隨系統語言（繁體中文系統顯示繁體中文，其他顯示英文），設定中可切換；所有介面文字兩種語言都完整、沒有漏譯。時間格式不另設選項，一律跟隨 Windows 的時間格式，所有時間顯示與輸入欄位格式一致（2026-11-04 變更：原為可選 12／24 小時）。
- 目前基準與目標：介面目前全為英文，沒有多語系。首發對象為台灣使用者。

### G-06｜深色模式（已規劃，**不納入首次交付驗收**）

- 怎麼判斷：跟隨系統主題；兩種主題下區塊文字對比都達標，球仍維持純色。
- 目前基準與目標：目前沒有深色模式。開發時程為首次交付之後的階段，待專案擁有者決定。

### G-07｜radial 選單中被 hover 的球有 juicy 手感

- 怎麼判斷：長按左鍵叫出 radial 選單後，滑鼠 hover 的那顆球出現「呼吸」或「波沿著圓周跑」的效果，離開後恢復；系統設定 `prefers-reduced-motion` 時不播放；球身仍是純色（現有 e2e 純色檢查須繼續通過）；動畫不改變用於命中判定與時間計算的幾何。手動目視驗收。
- 目前基準與目標：`DESIGN.md` 目前只定義側邊球 hover 放大（160 ms）與 radial 進場動畫（220 ms），沒有 radial 球的 hover 效果。效果的具體樣式（呼吸或圓周波，節奏、顏色）留到 PRD／設計階段再談。
- 設計規則的連動：這會與 `DESIGN.md` 的硬規則「沒有持續性裝飾動畫」衝突。專案擁有者已決定以此目標為準，到設計階段要同步把該規則修訂為「只有 radial 選單中被 hover 的球可有此效果，且 `prefers-reduced-motion` 時關閉」。

### G-08｜一次選取多個區塊，並一起移動或刪除（2026-11-06 新增，專案擁有者決定）

- 怎麼判斷：在日曆空白處按住左鍵並快速拖曳可框選已存在的區塊；選中多個後，拖曳其中一個即可整批移動（彼此的時間差不變），按 `Delete`／`Backspace` 可整批刪除；整批移動與整批刪除各可一次復原。拒絕分支（Escape、在日曆以外放開）整批回到原位且不寫檔。框選與 radial 長按不互相干擾。手動目視驗收＋自動測試。
- 目前基準與目標：目前一次只能選取一個區塊（`selectedEventId`），移動與刪除都只能一個一個做。
- 與 NG-03 的關係：本目標不建立新區塊，新事件仍固定 120 分鐘，不與 NG-03 衝突。
- 範圍外（本次不做）：加選（Shift）、批次改名或改顏色、複製、自動捲動、跨週框選、選取隱藏在可見時段之外的區塊；右側面板在多選時不顯示。

## 限制、假設、風險與決策

- **限制**：
  - 技術棧已定：Tauri 2、React、TypeScript、資料為本機 JSON 檔（來源：現有程式碼與專案擁有者確認）。
  - 離線、無帳號、無遙測。
  - 驗收平台為 Windows 桌面版；僅支援 Windows 10 版本 1803（組建 17134）64 位元或更高版本；更舊系統與 32 位元不支援（2026-11-04 決定）。
  - 安裝時若缺少 WebView2，允許安裝程式連網下載微軟官方版本；App 執行時仍不對外連線。
  - 不新增套件需先經專案擁有者同意（`AGENTS.md`）。
  - 開發工具放 D 槽（`CLAUDE.md` 第 3 節）。
- **假設**（若不成立，目標受影響）：
  - A-01 除了擁有者，還有一群人有相同痛點。若不成立，產品只服務擁有者本人，G-04、G-05 的投入價值降低。**確認者：專案擁有者；時機：首個 Windows 安裝檔完成後，找至少一位其他人試用。**
  - A-02 拖曳色球排時間，比輸入數字更快或更輕鬆。目前未量測，G-01 的代理證據（操作次數）取得後再比較。
  - A-03 台灣首發使用者偏好繁體中文介面。未驗證。
  - A-04 使用者不會把資料夾放進雲端同步資料夾。若不成立，可能發生資料遺失（見 R-01）。
- **風險**：
  - R-01 資料夾被放進 OneDrive 等同步資料夾，或開兩個視窗，可能造成覆寫。降低方式：G-02 的單一寫入者；README 說明建議。
  - R-02 未簽章安裝檔在 Windows 會跳出 SmartScreen 警告，可能嚇退使用者。接受此風險，README 說明如何繼續安裝。
  - R-03 e2e 測試不穩定，會削弱所有回歸判斷的可信度。原因已查出（拖曳測試腳本在放開滑鼠前沒有等待拖曳狀態完成），修法等專案擁有者同意。
  - R-04 桌面版從未在 Windows 實際啟動過，可能出現平台差異。優先在 G-03 驗證。
  - R-05 多語系與時間格式會牽動所有文字與時間顯示，容易漏改。降低方式：以測試檢查兩種語言的字串完整性。
  - R-06 開源專案尚未選擇授權條款，在選定前他人無明確使用權限。
  - R-07 免安裝版沒有安裝程式，若目標電腦缺少 WebView2 執行階段就無法由安裝流程補上（見 SRS U-12）。
