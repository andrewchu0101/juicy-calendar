## 處理結果（2026-11-07）

**決定**：專案擁有者原本想要「窄視窗時面板自動移到左側、並替它留出空間」，並要求最小視窗放不下時先報告實測。實測（模擬面板固定佔版面後的日曆寬度）：日曆需要 56＋84×7＝644 px，加面板 272＋間隔 16，視窗寬度要 ≥ 約 1040 才放得下；最小視窗 900 缺 141 px，而且換左邊或右邊都不影響日曆剩多少寬度。專案擁有者在 A～D 四案中選 **A：寬時固定佔版面，窄時收合**。所以**沒有實作「換到左側」**。

**行為**：
- 日曆區放得下「面板＋完整日曆欄」時，面板固定在日曆右側、日曆讓出寬度，不遮任何日期、欄位、活動或工具。2026-11-07 票 029 修正 12 小時刻度文字換行，時間軸由 56 擴至 80 px；目前手算邊界為週檢視 `80 + 84×7 + 272 + 16 = 956 px`、日檢視 `80 + 84 + 272 + 16 = 452 px`。下方 932／428 為原票實作當時的測試紀錄，保留歷史。
- 放不下時，面板自動收合成圓點，選取的活動不變；點圓點以浮層展開（只是暫時展開，**不寫入設定**）。展開的浮層仍在右側，會蓋住最右邊的欄位，這是使用者主動展開的結果。
- 使用者在寬視窗自己按「›」收合的偏好（`inspectorCollapsed`，存檔）不會被視窗大小覆寫。
- 圓點移到日曆左上角、時間軸那一格（原本在右上角，在窄視窗會蓋住「週日」的日期數字）。
- 多選時的「已選 N 個事件　刪除」仍在工具列；批次刪除與一次復原照常。

**程式**：`limits.ts` 新增 `GUTTER_WIDTH_PX`、`MIN_COLUMN_WIDTH_PX`、`INSPECTOR_WIDTH_PX`、`INSPECTOR_GAP_PX`（`CalendarGrid.tsx` 改引用）；`engine/layout.ts` 新增 `inspectorFits`；新增 `useElementWidth.ts`；`AppShell.tsx` 把日曆區改成一列（日曆＋面板）；`Inspector.tsx` 依 `docked` 決定固定、圓點或浮層。

**測試（先紅後綠）**：
- 單元 `inspectorFit.test.ts` 2 項（預期值手算：932、428）。紅燈：空殼回傳 `false`，2 項失敗。
- e2e `inspectorDock.spec.ts` 5 項（寬窗不遮、窄窗收合且同一活動仍選取並可編輯、縮小再拉寬、視窗大小不覆寫收合偏好、日檢視最小視窗放得下）。紅燈：面板蓋住 `day-header 5, 6` 與 `day-column 5, 6`（就是使用者看到的問題）；窄窗面板仍顯示。突變檢查（`inspectorFits` 永遠為真）使 3 項轉紅，已還原。圓點遮住週日標題是看了桌面截圖才發現的，先補測試看到紅燈（`day-header 6`、`day-column 6`）再修。
- 既有測試調整（**契約變更，不是放寬**）：`layout.spec.ts` 的 M-04 測試在 900×560 要先點圓點才看得到面板（2 處）；`core.spec.ts` 的「移動保持時長」「雙擊命名」要先選取、再依「面板已開」的版面量座標或外框，斷言不變。原因：選取活動時面板才佔版面，日曆欄會變窄。
- 結果：`typecheck`、`lint` 通過；`npm test` 443/443；`npm run test:e2e`（暫時設定改埠 1431）94 passed。
