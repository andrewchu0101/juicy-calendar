# 013：時間格式跟隨 Windows

**大小：** M　**狀態：** ready-for-agent（前置票完成後才能開始）

**成果（What to build）：** 區塊上的時間範圍、時間軸標籤、面板顯示值，一律依 Windows 的 12 或 24 小時設定顯示，與介面語言無關；App 不提供切換設定。

**Blocked by：** 010

**對應 TC／人工：** TC-12、M-05；AC-03.3、FR-10

**驗收指令：** `npm run typecheck`、`npm run lint`、`npm test`、`npm run test:rust`；人工 M-05

**要讀的規格段落：** `docs/04-sad.md` ADR-04；`docs/05-sds.md` API-06、`formatTime`；`docs/03-srs.md` R-7；測試計畫 TC-12、M-05

## 驗收條件

- [ ] 先寫 TC-12 並看到紅燈。
- [ ] 2026-11-02 當地 13:05：24 小時制 `13:05`；12 小時制英文 `1:05 PM`、繁體 `下午 1:05`。午夜、正午的繁體寫法暫定 `上午 12:00`、`下午 12:00`，**不阻塞**；時間範圍在 12 小時制的寫法未定，不驗。
- [ ] Rust 以 Windows 區域設定 API 取得 12/24 小時，直接宣告函式、不新增套件；取不到回傳空值，前端退回瀏覽器的 `hourCycle`；解析邏輯為可單獨測試的純函式。
- [ ] 程式中不再有寫死的 `HH:mm` 顯示格式。
- [ ] 人工 M-05：由專案擁有者切換 Windows 時間格式後檢查一致性，記錄結果；原生時間欄位若不一致，記為已知限制。
